# 管理功能设计说明

## 需求与边界

用户需要在界面上登录，然后维护「已纳入监测的项目列表」：改名、取消关注、置顶、查看详情。追加需求：端口可调整；改名只改显示名，目录名另设独立入口。

明确不做：多账号与角色权限、远程访问、云端同步、永久删除（v1 只做软删除）。

## 架构

```
manage_web.html  ←浏览器→  manage_ui.py（HTTP + 登录 + CSRF）
                                  │
                                  ▼
                           manage_store.py（数据层）
                                  │
                    overrides.json / state.json / INDEX.md
                                  │
                           archiver.py（原有流水线）
```

- 人工配置以**工作区路径**为键写 `overrides.json`，不用目录名。改名后配置不失联。
- 所有写操作持有 `Lock(target)` 与进程内串行锁，与每日定时任务互斥。
- 索引是**完整账本**：取消关注只在列表与 `find` 中隐藏，不删条目。

## 字段语义

| 字段 | 写入位置 | 作用 |
|---|---|---|
| `title` | overrides.json | 显示名；README 与索引优先取它；目录名不变 |
| `watching=false` | overrides.json | 取消关注；列表/`find` 隐藏，「全部」可见 |
| `pinned=true` | overrides.json | 索引与管理列表置顶 |
| `note` | overrides.json | 人工备注，仅管理台展示 |
| `skip=true` | overrides.json | 停止归档（删除操作设置） |

## 改名与目录改名分离

- `rename()`：写 `title` + `state.name`，设 `name_source="manual"`。`render` 见到 manual 就不再按 LLM 摘要改名。
- `rename_dir()`：只做 `os.rename`，改 `state.dir`。显示名不受影响。
- 两者均先备份 `state.json`/`overrides.json`/`index.json`/`INDEX.md` 到 `_trash/_manage_backups/`，失败整体回滚。
- 目录名做严格校验（禁止 `\/:*?"<>|`、`.`、`..`），不调用 `safe_name` 悄悄替换——避免 `a/b` 变成 `a b` 这种意外路径。

## 认证

- 口令首次随机生成（16 字符）只打印一次；环境变量 `ARCHIVER_MANAGE_PASSWORD` 可覆盖。
- 存储 salt + PBKDF2-SHA256（20 万轮）哈希，明文不落盘。
- 会话 Cookie：HttpOnly + SameSite=Strict + 8 小时过期；CSRF token 只在登录响应体返回，写操作校验 `X-CSRF-Token`。
- 连续 5 次口令失败锁定 60 秒。仅绑 `127.0.0.1`。

## 踩坑记录

1. **LLM 摘要会覆盖人工改名**：`render` 里 `st.name != s.title` 就重命名目录。必须加 `name_source != "manual"` 守卫，否则人工改名下次 `run` 就被改回去。
2. **`safe_name` 不是校验器**：它把非法字符替换为空格。目录名入口必须自己用正则严格拒绝，否则 `a/b` 会静默变成 `a b`。
3. **`skip=true` 不会清理旧目录**：原代码只在扫描时跳过，不动已归档目录。删除操作要显式调用 `trash_project()`。
4. **index.json 结构不能随便加字段**：无管理字段时必须保持原样，否则既有测试与幂等性被破坏。做法是先生成原结构，再按显式字段追加。
5. **测试里不能硬编码家目录**：仓库有 `test_public_content` 扫描真实用户名路径，测试文件也要用 `__file__` 推导路径。
6. **测试目录改名时显示名来自 `_summary.json`**：断言「显示名不变」要记录操作前的值，不能假设等于 `state.name`。
